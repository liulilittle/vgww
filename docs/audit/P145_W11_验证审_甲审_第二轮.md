## ② 根因

**ROOTCAUSE（B2）**：`src/proto/dhcp6.cpp:570-580` 的 `StaticLeaseFor` 用循环查找首个同 DUID 记录，命中后 `it = leases_.erase(it);` 立即 `return &leases_.emplace(key, …)`（:575-577）——**只擦除第一条便返回**，其余同 DUID 记录原样留存。而注释 :562-565 声称 “drops the stray ones”（复数）。

**污染入口**：`src/proto/dhcp6.cpp:1339-1345` 的载入器只按 IP 尾 8 字节去重（`claimed_ips.insert(tail)`），**不按 DUID 去重**；因此持久化文件可以合法注入同一 DUID 的多条记录，随后静态分支无法收敛。

**可观测后果**：一条静态绑定可长期占用多条记录；静态记录永不 Sweep（:581-584 注释明示），所以这些多余记录是永久性占用，直至进程重启。

## ③ 方案

**最小修复（仅 dhcp6.cpp 的 StaticLeaseFor）**：把“命中即删即返回”改为“先记录首个命中项、继续扫描并擦除所有同 DUID 记录、最后以调用方 key 插入一条”：

```
Lease* first = nullptr;      // 保留一条作为承载
for (auto it = leases_.begin(); it != leases_.end();) {
    if (it->first.duid == key.duid) {
        if (nullptr == first) { Lease carried = it->second; it = leases_.erase(it); first = &leases_.emplace(key, std::move(carried)).first->second; }
        else { it = leases_.erase(it); }   // 清掉 stray
    } else { ++it; }
}
if (nullptr != first) return first;
```

**回归红证要求**：新增测试须先构造“经 LoadLeases 注入 2 条同 DUID 记录”，再 `Acquire` 断言 `LeaseCount()==1`；在本轮变异下必须变红。
**边界**：`exact` 命中的快速路径（:566-569）不需要改，因为该路径本身就只对应一条记录。

**须请执行侧确认**：`drops the stray ones` 是产品契约还是仅注释笔误。若不打算支持“多记录并存”，也可改为在载入器侧按 DUID 去重（`dhcp6.cpp:1339` 处增加 DUID 集合），二选一即可，但**必须有测试钉住**。
