## ② 根因

**ROOTCAUSE（B2-a 残留）**：`src/proto/dhcp6.cpp:566-569` 的 `exact` 快路径在进入全表扫描（`:570-593`）**之前**直接 `return &exact->second;`。当调用方 IAID 恰好命中某条已存在记录时，同 DUID 的其他记录不会被清理。

**触发条件（窄）**：必须同时满足 ①持久化文件里存在同 DUID、多 IAID 记录；②客户端随后的 `Acquire` 使用的 IAID 恰好等于其中一条的 IAID。
**影响（有界）**：残留记录是 `is_static=false` 的动态记录，到期被 `Sweep` 回收（实测 `+7200s → table=1 swept=1`）。不会永久泄漏，但期间会短暂占用表槽。

---

## ③ 方案

**最小修复**：把 `exact` 快路径改为「命中即记下指针不返回」，与全表扫描合并——扫描时把 `it->first == key` 的那条也视为同 DUID 记录一并 erase（或直接删除 `:566-569` 的早退，令全表扫描统一处理）。

```
// 删除 566-569 的早退；全表扫描已能正确落到 key
Lease carried{}; bool found = false;
for (auto it = leases_.begin(); it != leases_.end();) {
    if (it->first.duid == key.duid) { if (!found) { carried = it->second; found = true; } it = leases_.erase(it); }
    else { ++it; }
}
if (found) return &leases_.emplace(key, std::move(carried)).first->second;
```
注意：删除早退后每次静态请求都多一次 O(n) 扫描。若性能敏感，可保留早退但先做「同 DUID 计数==1 才早退」的判定：`if (exact != end && count_duid(key.duid) == 1) return &exact->second;`。
**验收测试**：`LoadLeases` 注入 `{duid, iaid=7}` 与 `{duid, iaid=2}` 两条，`Acquire(duid, 7)` → 断言 `LeaseCount()==1`（当前会红）。
**move 语义**：`Lease` 成员为 `array<uint8_t,16> / uint32_t / time_point / bool / std::string`（[READ src/proto/dhcp6.h:144-150]），`std::move(carried)` 后不再读原对象，**安全**。

## 反思（第 9 条，覆盖全程）

1. **我上一轮的 B2 严重性判断偏重**：我曾写「永久性占用，直至进程重启」。本轮实测 stray 是动态记录、Sweep 可回收（`+7200s → table=1 swept=1`）。**教训**：断言严重性前必须验证记录类型（`is_static`）与回收路径，而非只看「静态记录不 Sweep」的注释。
2. **我上一轮的修复方案不完整**：只要求「扫描全部同 DUID」，未指出 `exact` 快路径会绕过该扫描。执行侧照此实现后 case2 仍失败。**教训**：给方案时必须枚举**所有**控制流出口（本例的 `exact` 早退正是被忽略的出口）。
3. **门禁参数曾误报**：我复跑 C0 时误用 `-- -m:1` 触发 `MSB1031`，初看像编译失败；核对日志后确认是参数错误，改用不带 `-m` 通过。**教训**：看到 `err>0` 必须先分类（`error C` vs `error MSB`）。
4. **固化做法**：本轮所有结论均锚定单一库 SHA（`C3698FCC…`），并在探针内写显式前置断言（`loaded=2`）、给出 case 编号，避免再次出现旧库假证。
