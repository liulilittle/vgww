## 1. P1 语义等价

### 1.1 结构改动范围(逐段核对 diff)
`git diff -w -- src/runtime/dataplane.cpp` 的全部 +- 行只有:

- 新增内层 `for (size_t b = 0; b < count; ++b){ TxFrame& frame = tx_buf[b];`(dataplane.cpp:2179-2180)+ 闭合 `}`(dataplane.cpp:2251)。
- 逐帧 body(下行限速 → 每客户端下速率会计 → bridge egress 解析 → AppendDown)**一行未动**:
  [READ:src/runtime/dataplane.cpp:2181-2250](rate_limiter_.AllowDownlink / live_rates_ / bridge_table_.Lookup / AppendDown 与 HEAD 版本逐字一致,仅缩进 +4)。
  [BASH:git -C F:\vgww diff -w -- src/runtime/dataplane.cpp] → 输出仅上述壳层行。

### 1.2 严格 FIFO
`PopBatch(out,max_out)` 的取值口径([READ:src/dsp/spsc_ring.h:111-131]):
`count = min(tail-head, max_out)`;循环 `out[i] = std::move(SlotAt(head+i))`(`head+i` 严格递增)→ 返回后 `head += count`。
故一次 `PopBatch(out,64)` 的 `out[0..count-1]` = 环内 `head..head+count-1`,与旧「反复 `PopBatch(&frame,1)`」取出的序列**逐元素相同**;多次 PopBatch 之间 head 续接,跨批也不重排。
实测:[BASH:temp/p144_w11_a_review/probe_batch_drain.exe] → `n=1/63/64/65/200/4096` 全部 `order_ok=1`、`rem=0`(零残留)。

### 1.3 continue 丢弃语义
旧:`while (PopBatch(&frame,1))` 内 `continue` → 直接进下一次 PopBatch,即「跳过本帧,取下一帧」。
新:`for (b...)` 内 `continue` → `++b`,即「跳过本帧,处理批内下一帧」。
两者都满足:**该帧已被 pop(计入 head,所有权已转移),后续处理(会计/egress/AppendDown)被跳过**。批内被丢帧不影响后续帧顺序(后帧按 b 升序继续)。
[READ:src/runtime/dataplane.cpp:2193] `continue;  // drop: TCP retransmits as needed` 位置未变,drop 语义等价。

### 1.4 单次 flush 位置未变
`FlushPortBatch(down.primary/down.downstream/up...)+LatTraceFlush()` 仍只在两条循环全部结束后执行一次([READ:src/runtime/dataplane.cpp:2254-2258]),与 HEAD 一致。

**结论:P1 语义等价成立。**

## 2. P1 SPSC 单写单读安全性

M(spsc) 契约([READ:src/dsp/spsc_ring.h:10-20, 95-131]):
- 满判 `tail-head == capacity`(自由跑 64 位索引,ABA 需 2^64 次操作不可达);
- Push release-store tail、PopBatch acquire-load tail、pop 后 release-store head;
- PopBatch 不阻塞、无等待唤醒,纯「轮询取走」。

全仓 `tx_rings` 引用点([BASH:Select-String tx_rings src/ tests/]):

| 角色 | 位置 | 线程 |
|---|---|---|
| 生产者 | dataplane.cpp:2003/2025/2074 (`t_worker_index` 专属) | 各 worker |
| 生产者 | dataplane.cpp:3133 (HandleIcmpReply) | worker(icmp socket 回调经 `io_contexts[i]->poll()`,[READ:dataplane.cpp:982-985, 2968]) |
| 生产者 | dataplane.cpp:3193 (HandleUdpV6 lambda) / :3290 (HandleUdp lambda) | worker |
| **唯一消费者** | **dataplane.cpp:2174 `PopBatch(tx_buf,64)`** | **RX/TX 线程(RxTxLoop)** |
| 销毁 | dataplane.cpp:1442 `tx_rings.clear()` | Stop 路径(线程已 join,[READ:dataplane.cpp:1317-1318]) |

- 每 ring `i` 的唯一生产者恒为 worker i(`t_worker_index=i`;[READ:dataplane.cpp:2923-2924]);bridge 线程不直接写 ring(经 `bridge_control_queue_` → RX 线程 `DrainBridgeControl`,[READ:dataplane.cpp:2160-2162, 1803-1830])。
- **batch 不引入新风险**:batch 化只把「N 次单元素 pop」合并为「1 次多元素 pop」,索引推进仍是单次 `head.store(head+count, release)`;生产者只在 `Push` 里前进 tail,与消费批大小无关。故不会产生「跨批重排」(取出的槽位永远按 free-running 索引递增)、不会 ABA(2^64 不可达)、不会丢帧(每次 pop 只取 `tail-head` 已发布元素;n=4096 实测零残留)。
- 生命周期:PopBatch 把元素 move 进 `tx_buf`,随后由 `AppendDown` **拷贝**进 `INTERMEDIATE_BUFFER`([READ:dataplane.cpp:3759-3789]),故 `tx_buf` 槽位在下次 PopBatch 被覆写不影响已提交帧。

**结论:SPSC 契约成立, batch 未引入 ABA/丢帧/重排。**

## 3. kTxBatchMax=64 的栈占用与「rx_batch>64 多轮不丢帧」

- 实测 `sizeof(std::vector<uint8_t>) = 24`(x64 MSVC),`24 × 64 = 1536 B = 1.5 KiB`
  [BASH:temp/p144_w11_a_review/probe_batch_drain.exe] → `sizeof(TxFrame)=24 kTxBatchMax=64 total=1536 bytes`。
  与代码注释(dataplane.cpp:62-63)一致。
- 内层 `while(true)` 在 `count==0` 时才 break([READ:dataplane.cpp:2176-2178]),故环内帧数 >64 时由多轮 PopBatch 取尽:
  实测 `n=200 → pop_calls>=4`、`n=4096 → pop_calls>=64`,全部 `order_ok=1 rem=0`。
  kTxBatchMax 与 `config.perf.rx_batch` 无耦合(常量,不读配置),互不影响。
- 非阻断观察(P4):`tx_buf` 声明在 `while (running)` 内([READ:dataplane.cpp:2171]),每次 RX 唤醒构造 64 个空 vector(约 1.5 KiB 零化),即使 TX 环全空也发生;相对每帧 syscall/拷贝可忽略,但若日后追 PPS 可上提作用域复用。

**结论:成立。**

三次独立来源一致性:执行 AI 0.853/0.949([READ:build_s4/p144_w11_mutation_evidence.log:27-28])、乙审 0.874/0.922、甲审 0.866/0.993、ctest 日志 0.873/1.027([READ:build_s4/Testing/Temporary/LastTest.log:10-11])。

方法学评估:
- 同进程比值 + 5 次交替取 min + 两者同一 fill/drain 循环([READ:tests/test_spsc_ring.cpp:186-231,242-263]) → 抗调度抖动,与 memory.md「同进程比值优于绝对耗时」一致;
- 主形状用 malloc-free `Frame`([READ:test_spsc_ring.cpp:191-197])隔离环自身原子成本 → 0.853~0.874,即 **环索引原子对摊销真实存在(约 -13%)**;
- 真实帧形状(`std::vector`)明确标注 informational([READ:test_spsc_ring.cpp:270-303]),0.92~1.03 说明**分配 churn 盖住收益**,上限 2.0 仅防回归 —— **如实**。
- checksum 防空跑([READ:test_spsc_ring.cpp:262,300]).

**收益评估:环成本 13% 为真;热路径真实帧收益有限(≈0~5%)且可能被抖动吃掉。保留价值:零行为变化 + 零回归 + 锁定批量 drain 的 FIFO 回归网 + 与 rx 侧 batch=64 风格一致 → 建议保留(与乙审一致)。**
