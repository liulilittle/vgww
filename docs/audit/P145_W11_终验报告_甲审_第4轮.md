## ② 根因（对 MUT-1「等价变异」判定的证伪）

**执行侧/主代理判定**：MUT-1（carrier 取最后一条）不红，因静态两分支在 `StaticLeaseFor` 返回后无条件覆写 `ip/is_static/expires/hostname` ⇒ 等价变异。

**我的证伪**：该论证对 **config 分支**成立，对 **runtime 分支不成立**。
- [READ src/proto/dhcp6.cpp:652-654] runtime 分支：`if (!hostname.empty()) { lease.hostname = reported_name; }` —— **仅当调用方传入非空 hostname 才覆写**。
- [READ src/proto/dhcp6.cpp:668-672] config 分支：`if (!hostname.empty()) { … } else { lease.hostname = binding.hostname; }` —— 有 else 兜底，故 config 分支确实不可观测。
- [READ src/proto/dhcp6.cpp:1837-1840]、[READ src/proto/dhcp6.cpp:1857-1859] 生产路径 `HandleFrame` 调 `Acquire` 时 hostname 实参为 **`std::string()`（空）**。

因此：runtime 绑定 + 空 hostname 时，carried 记录的 hostname **直接泄漏**给调用方。

**实测（独立变异，第 16 条）**：
1. 在 `temp/p145_mut4/dhcp6_mut.cpp` 施加 MUT-1（`if (!found)` → `if (true)`），独立编译 obj（`temp/p145_mut4/dhcp6_mut.obj`），`/FORCE:MULTIPLE` 优先于 lib 链接。**未触碰 build_s4**。

## 反思（第 9 条，覆盖全程）

1. **我上一轮判定错了方向**：我认定 `exact` 快路径有害并要求删除，执行侧照做——但删除本身是对的；真正的问题是**主代理对 MUT-1 的「等价变异」判定**，我本轮通过构造 runtime 分支 + 空 hostname 的探针把它证伪了。教训：判定「等价变异」必须穷举**所有**赋值路径（本例 config 有 else 兜底、runtime 没有）。
2. **我又一次被陈旧二进制误导**：17:06 的 exe 配 17:09 的 lib 导致 `:3226/:3230` 假红。教训：跑测试前必须核对 exe 与 lib 的 mtime/SHA，或显式重建 target。
3. **我在探针设计上犯了两次错**：先 `UpsertBinding` 后发现 `ReplaceBinding:1673-1679` 会清空该 DUID 的 lease（首版探针 `table=2→0` 得空结论）；改为「先 upsert 再 load」才有效。教训：调用顺序本身就是探针语义的一部分，必须先读实现确认副作用。
4. **未验证项（W5）**：V8 的 v4/v6 常量换位无运行时红证（两常量同值），我仅作静态核验；`TestB81DumpLeasesDoesNotStallLockHolders` 的时序断言本轮未单独复跑。

**不足**：我只能证明「MUT-1 可观测」，但**无法证明** carrier 必须取「首条」而非「末条」——这是产品语义选择。故我的结论是「必须补测试钉住语义」，而非「实现错误」。
