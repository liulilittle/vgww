## B-1 [P1·真BUG] settings.cpp - batch33i 空 adapter 自动选中与保存值脱节(甲审 B 项,双方确认)

### 证据
- 自动选中只写局部变量:`src/ui/pages/settings.cpp:1439-1441`
  ```
  if (selected.empty() && !choices.empty()) {
      selected = choices.front().value;
  }
  ```
- picker 显示被改写:`settings.cpp:1446 adapter_pick_->SetSelectedValueSilent(selected);`
- `adapter_value_` 唯一写点是用户 on_changed(`settings.cpp:816-821`)与 FillControls(`settings.cpp:1287`);
- ReadDraft:`settings.cpp:1226 draft.adapter = adapter_value_;`(独立成员,非 picker 选中值);
- SelectElement::SetSelectedValueImpl `if (value == selected_) return;`(controls.cpp:3877-3879)——已选中行再次点击也不触发 on_changed;
- core 不拒空 adapter:`src/core/config.cpp:1414` 仅 `if (config.adapter.size() > kMaxAdapterBytes)`;
- Save 可点条件 `adapters_empty_ && adapter_value_.empty()`(settings.cpp:1657)在"有网卡、空配置"下为 false → Save 可用。

### 根因链与可达性
首次运行/空配置(config.adapter="")且检测到 ≥1 个 adapter:
1. Update→RefreshAdapterOptions 把 picker 显示自动选为最可用设备,但 `adapter_value_` 保持 ""。
2. 用户看到 picker 已选中 NIC 1 → 点 Save → `draft.adapter = ""` → ToConfig 写空。
3. `core::ValidateConfig` 只查长度,空值落盘。
4. 下次启动数据平面绑定失败;设备表/仪表盘显示无绑定。

用户操作路径:首次运行不进向导、直接进设置保存;或配置文件本无 adapter 字段。破绽到下次启动才显现——"显示与保存不一致"操作坑。

### 最小修复方案
```
if (selected.empty() && !choices.empty()) {
    selected = choices.front().value;
    adapter_value_ = selected;  // 与 picker 显示保持一致
    RefreshAdapterPathRow();
}
```
(需确认只在"空配置缺省"分支赋值,不在 shown 已匹配分支。)

### 测试缺口
`tests/test_ui.cpp:34418-34473`(TestB33iEmptyAdapterDefaultsToBest)只断言 picker 的 selected_value,不断言保存命令的 `config.adapter`。

## B-2 [P1·真BUG] dashboard.cpp - WAN 过滤器恒空 + LAN 列恒"是"(甲审 F1 升 P1,双方确认)

### 证据
- 数据源只发布 lan=true 客户端:`src/runtime/dataplane.cpp:4036-4044`(非 `IsLanClientAddress` 者 `continue`)且 `rate.lan = true`(:4048);

## B-3 [P1·受限·真BUG] 异步 apply_live 失败后重存被吞(甲审 F2,双方确认)

### 证据
- `save_guard_armed_` 唯一解除点:`src/ui/pages/settings.cpp:1469-1471`(RefreshDirty 发现 dirty 时);
- Save 进入即武装:`settings.cpp:1689-1692`;Post 失败解除(:1723);ToConfig 失败解除(:1714);
- **异步失败路径**:Execute 返回后 UI 仅收 toast(Danger),`save_guard_armed_` 仍为 true;
- 重存被吞:`settings.cpp:1690 if (save_guard_armed_) return false;`——用户不改任何字段再点保存 = silent no-op(无 toast、无任何反馈)。
- 失败只在 app.cpp 广播 OnCommandFailed(`src/ui/app.cpp:1111-1129`),settings 页未实现 `OnCommandFailed`。

### 可达性
保存后 `apply_live` 失败(端口被占/驱动拒绝/配置无法热加载),用户确认错误后不编辑直接重存 → 无任何响应。受限:仅在 apply 失败且未编辑时。

### 最小修复方案
1. app.cpp 失败分支已广播 OnCommandFailed;
2. settings 实现 `OnCommandFailed()`:`if (save_guard_armed_) { save_guard_armed_ = false; }`(或埋在 batch42 失败分支同一处,按 auditor 取舍)。

### 测试缺口
`tests/test_ui.cpp:27001-27017` 只断言失败 toast 不派 "CommonSaved",未测"失败后重存"路径。

## B-4 [P2·窗口缺陷] settings.cpp - 保存 Web Token 后的 dirty/guard 窗口(甲审 A 项,乙审反证后降级,双方盖章)

### 修正(乙审反证,甲审认可)
甲审原判"dirty 永真 / mirror 永 false / ConfirmLeave 恒打扰 / guard 永解除"四连锁**不持续**:
- `settings.cpp:1619 applied_ = from_snapshot;` 无条件是 Update 的开场(非仅 mirror 分支);
- FromConfig(`settings.cpp:205-241`)从不读 web_token(token write-only 不进快照)→ `from_snapshot.web_token` 恒 "";
- Save 后 worker `RequestRefreshAfter(0)`(`src/ui/snapshot.cpp:335`)→ ≤~200ms-1s 内 Update 覆盖 `applied_` → 下一 RefreshDirty 断言 `ReadDraft("")==applied_("")` → dirty false、guard 复武装、mirror 恢复。自愈。

### 实际窗口
`settings.cpp:1726 applied_=draft`(web_token=输入值)→ :1734-1736 清空输入框 → :1737 RefreshDirty:`ReadDraft().web_token=""` vs `applied_.web_token` → dirty=true + guard 解除。
窗口 = [Save 后, 下一个快照]。窗口内连点 Save → **重发 SaveConfigCmd、二次重启 data plane、双 toast**;dirty badge 窗口内闪烁(两次 Relayout)。仅 token 型保存开启该窗口(普通保存 applied_==控件,guard 保持武装)。

### 最小修复方案
```
token_input->SetValue(std::wstring());
applied_.web_token.clear();   // 基线同步可见控件,消窗口
```
(或窗口内禁用 Save 按钮——保存后直到首个新快照。)

### 测试缺口
`tests/test_ui.cpp:5717-5898`(TestB269)只断言命令 token 载荷;:5856-5858 注释承认"token 回空不足以使 draft==applied_"。

## B-7 [P2·视觉] format.cpp - FixedTimeText 超过 99 小时列宽扩展(甲审 E,双方认可并修正可达性)

### 证据
`src/ui/format.cpp:78-86`:`L"%02llu:%02llu:%02llu"`——`%02` 是最小宽度,>99h 输出 3+ 位。format.h:27-29 注释称 "the shape never changes after a week of uptime"(168h 已超 2 位)。
测试:`tests/test_ui.cpp:29642-29649` 仅到 90000s=25h。

### 可达性(甲审修正)
比 uptime 更易触发:租约可取 8760h(v4)/31536000s=8760h(v6)。一年期 DHCPv6 租约在 leases 页立即渲染 "8760:00:00"(4 位)。非崩溃(48 缓冲足够),列宽抖动视觉 P2。

### 最小修复
`std::min(seconds/3600, 99u)` 上限(截断显示)或固定 4 位小时(合法租约 <10000h)。需产品意图;不改不构成正确性 BUG。
